Creates and initializes a new instance of an \doxylink{struct_l_d_l___fps_limiter}{LDL\+\_\+\+Fps\+Limiter}. 

This function allocates memory for a new FPS limiter object and configures it to target a specific number of frames per second. The success or failure of the allocation is reported via the provided result pointer.

\end{DoxyReturn}
\begin{DoxyNote}{Note}
The returned FPS limiter must be freed using LDL\+\_\+\+Fps\+Limiter\+Destroy when it is no longer needed to avoid memory leaks.

\item 60:\+ Standard for most applications and games

Regulates the execution speed by introducing a delay if necessary. 

This function checks the elapsed time since the last call to {\ttfamily \doxylink{_fps_limit_8h_a74f1a9709178aab070401f0b561aacf2}{LDL\+\_\+\+Fps\+Limiter\+Mark}}. If the application is running faster than the configured target Frames Per Second, this function will block (throttle) the current thread for the required amount of time to bring the execution speed back in line with the target limit.


\begin{DoxyParams}{Parameters}
{\em fps\+Limiter} & A pointer to the \doxylink{struct_l_d_l___fps_limiter}{LDL\+\_\+\+Fps\+Limiter} instance responsible for performing the throttling operation.\\
\hline
\end{DoxyParams}
\begin{DoxyNote}{Note}
This function should be called at the end of each frame after all processing and rendering is complete. 

The delay is calculated as:\+ delay = (1 /\+ target\+\_\+fps) -\/ elapsed\+\_\+time 

If the application is already running at or below the target FPS, no delay is introduced. 

This function uses LDL\+\_\+\+Delay for sleeping, which may not be perfectly precise due to OS scheduling. 

For high-\/precision timing, consider using spin-\/locks or busy-\/waiting for very short delays.
\end{DoxyNote}
